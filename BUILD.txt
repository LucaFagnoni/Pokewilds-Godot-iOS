BUILD AND EDIT

DESKTOP
1. Install the same Godot Standard engine used for the snapshot: the local binary
reports 4.7.2.stable.official.ed1daf0bf. Use matching export templates. Engine,
SDKs and export-template binaries are external dependencies, not bundled here.
2. Import project/project.godot. Allow asset imports to finish, then press F5.
The .godot cache is intentionally absent and is regenerated locally.
3. The project contains its default Gen 3 overhaul pack in data. Retain it.

ANDROID
1. Install JDK 17, Android SDK and matching Godot Android export templates.
The included Gradle config specifies compile SDK 36, Build Tools 36.1.0,
NDK 29.0.14206865, Gradle Android plugin 8.6.1 and Kotlin 2.1.21.
The export preset specifies min SDK 24 and target SDK 35.
2. Configure your own Java and Android SDK paths in Godot Editor Settings.
3. Obtain the matching android_source.zip from your export templates. Extract it
into a separate temporary folder. Copy its libs/ directory into
project/android/build/libs/. Keep the included custom src/ and res/ files.
Do not replace the custom Android wrapper with a stock build template: it contains
the save-file bridges, document provider and launch behavior used by this game.
4. Open Project > Export > Android. Gradle build is enabled. Internet permission
is enabled for multiplayer. Verify package com.pokewilds.godot and architectures.
5. Use your own debug or release keystore. No signing credentials are supplied.
A differently signed APK cannot update the existing signed app in place; back up
saves before installing a separately signed build. For development, choose a
separate application ID to avoid replacing the installed game.
6. Export into a new build directory and test on devices. Test first launch,
GAME FILES folder selection, save/load, controller input, and multiplayer.

EMBEDDED ZEROTIER (MULTIPLAYER)
MULTIPLAYER needs no ZeroTier app, account or network owner. The Android build
embeds libzt and joins a ZeroTier ad-hoc network (controller-less, no member
list or limit, IPv6 TCP to the game port only). The network ID is derived from
the game port in PokeWildsZeroTier.java; nothing has to be created anywhere.
1. Fetch libzt with submodules next to this package (../third_party/libzt), then
run ./build_libzt_android.sh with ANDROID_HOME set. It writes
project/android/build/libs/zerotier/libzt-release.aar, which build.gradle includes.
The Android export will not compile without this file, because
PokeWildsZeroTier.java uses the libzt classes. Use CMake 3.22 from the SDK;
CMake 4 rejects libzt's CMakeLists.
2. Ad-hoc networks cannot broadcast, so JOIN GAME reads its list from the small
lobby directory in lobby-directory/ in this package (a Cloudflare Worker; node
test/directory.test.mjs runs its tests, node test/local_server.mjs runs it
locally). A build reads the directory's settings from project/lobby_server.txt,
which is not part of this package. Without that file the game builds and runs,
and JOIN GAME reports that no lobby list is set up. To use the menus over the
internet in your own build, deploy lobby-directory/ yourself and supply your
own file. Testers can override the address without a rebuild with
[lobby] url="..." in zerotier.cfg in the game data folder. Only the lobby list
uses it; play is player to player and relies on ZeroTier's public root servers
for peers to find each other.
3. Desktop builds and Android builds without libzt use the same menus over the
local network instead (UDP 54556 broadcast for the list, TCP 54555 for play).
Add force=true under [lobby] to make them use the directory for testing.
libzt is under the ZeroTier BSL 1.1; see LICENSES/ZeroTier-libzt-BSL-1.1.txt
and check its terms against the GPL scope before publishing binaries.
